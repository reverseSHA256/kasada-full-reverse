## 1. VXN Decoded

**`vxn` is NOT a single secret value - it's the PoW parameters object:**

```javascript
vxn = {
    qdw: 10,    // difficulty (number of leading zero BITS in hash)
    xqn: 2,     // number of mining rounds
    zsr: ""     // challenge nonce from /tl response (initially empty)
}
```

- `qdw` = difficulty level (requires hash with N leading zero bits)
- `xqn` = number of rounds (iterations of hash chaining)
- `zsr` = server challenge string (populated from dynamic config or /tl response)

## 3. PoW Mining Algorithm

### Mining Closure (addr 46334)

Receives 3 arguments:
- `arg1` (scope[1966]) = **nonce string** (hex, generated randomly)
- `arg2` (scope[1967]) = **vxn override** (if not null, replaces state.vxn)
- `arg3` (scope[1968]) = **ykj value** (extra data, stored in result)

// Round 2 (if xqn >= 2):
hashInput = result.concat(nonce.slice(0, 16));  // previous hash + same nonce prefix

## 4. Nonce Generation

The nonce is a random hex string generated by:
- `scope[402]()` → returns `{qdw, xqn, zsr}` (vxn params)
- `scope[403]()` → returns `ykj` value (HMAC key string)
- The nonce itself (scope[2029] = R7, 4th arg to closure) comes from the PoW driver

At addr 9617-9694, nonce generation uses:
```javascript

```

## 6. HMAC Key Derivation

The HMAC key is **hardcoded** in the bytecode:
```

```

At addr 22399, the HMAC function is set up as:
```javascript

```

The `x-kpsdk-h` header (scope[300]) uses HMAC-SHA256 with the `ykj` key
to sign the request (CT + CD + request details).

## 7. Key Encryption Values

```
jpk = "CV7o9fRC/gx24wn2aw7QVuED7ds="  // AES key (base64, 24 bytes)
rpk = "CV7o9fRC/gx24wn2"               // IV or short key (16 bytes)
```

These are used for encrypting/decrypting the CT token.

## 8. Complete PoW Seed Formula

```
hash_input = "tp-v2-input" + nonce.slice(0, 16)
```

The seed is literally `"tp-v2-input"` concatenated with the first 16 hex characters
of the random nonce. SHA-256 is applied, and the result must have `qdw` (10) leading
zero bits. For round 2, the previous hash output replaces "tp-v2-input".

## 9. What Updates from /tl Response

The `dynamicConfig` field (addr 44218) from the /tl response can update:
- `ewm.zsr` - the server challenge nonce
- `ewm.qdw` - difficulty adjustment
- `ewm.xqn` - round count adjustment

When `zsr` is non-empty, it becomes part of the vxn object passed to mining,
but based on the bytecode analysis, **the actual hash input formula doesn't use zsr directly** -
it only uses `exn + nonce.slice(0,16)`. The `zsr` may be included in the CD payload
as proof that the client processed the challenge.
